# Sine tables and precalculation

A sine wave is useful for smooth periodic motion, but we do not need to calculate trigonometry on the 6510 every frame.

Instead, generate a byte table ahead of time:

```asm
sine:
    .byte 100,102,105,107,110
    ; ... generated values ...
```

Runtime code becomes an indexed lookup.

```asm
    ldx phase
    lda sine,x
    sta $d001
    inx
    stx phase
```

The exact range, length and phase mapping are design choices. A host-side generator is acceptable because the C64 still consumes transparent, inspectable data.

## Scene connection

**Why does a demo coder care about this?**

Sine motion is a scene vocabulary item, but the deeper lesson is precalculation. Use powerful development machines to prepare data so the C64 spends its scarce cycles on the visible effect.

Multiple phase-shifted lookups can produce waves, sprite formations, DYCP motion and many other effects.

## Lab

Generate or hand-author a small periodic table and use it for sprite Y. Change amplitude and center. Inspect the generated bytes rather than treating the generator as magic.

## Checkpoint

You understand a sine table as precalculated effect data and can use phase-indexed lookup for periodic movement.
