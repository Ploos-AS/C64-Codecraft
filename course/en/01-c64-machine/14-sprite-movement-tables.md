# Sprite movement tables

A movement table stores positions prepared in advance.

```asm
    ldx phase
    lda xpos,x
    sta $d000
    lda ypos,x
    sta $d001
```

Incrementing `phase` selects the next pair of coordinates. When the table ends, wrap the phase back to the beginning.

For 9-bit X movement, keep the ninth-bit information in a companion table or derive it in a controlled way.

## Why tables?

Complex movement can be expensive to calculate every frame. Precalculated tables exchange memory for predictable runtime work.

The table can be authored by hand, generated by a script, or exported by a tool. The runtime representation remains ordinary bytes that the 6510 reads directly.

## Scene connection

**Why does a demo coder care about this?**

Precalculation is one of the central demoscene techniques. A table can turn expensive mathematics into a few indexed loads with predictable timing.

## Lab
